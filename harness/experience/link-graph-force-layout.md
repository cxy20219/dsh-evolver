# 链接关系图的力学：度中心性、核心-外围与稳定性边界

## 适用场景

改概览页「链接关系图」（`client.js` 的 `computeLinkLayout`）的布局、节点大小或力参数时。

## 目标形态与它由哪个量负责

用户要的是「核心-外围」：连线多的卡片大、居中，邻居紧凑围成光晕，低度数卡片留在外围。四个量各管一段，缺一段就退回一坨云：

| 观感 | 实现 | 位置 |
|---|---|---|
| 枢纽的圆明显更大 | `density * (2.2 + 5.8 * w^0.75)`，`w = deg / max(2, 最大度)` | `radiusOf` |
| 枢纽不把邻居挤扁 | 排斥力乘两端 `mass = 0.6 + 0.9w` | 主循环 |
| 邻居围着枢纽成光环 | 连线静止长度 `18 + 44*(1 - 两端 w 的平均)`：枢纽两端 18、枢纽-叶子约 37、叶子-叶子 62 | `springs` |
| 枢纽在内、叶子在外 | 向心力 `0.18*(0.2+0.8w) * min(d, 220)`；碰撞间隙 `5` | 主循环 / `separate` |

种子按度数排序的螺旋（枢纽在内圈），配合降温 `alpha = 0.988^step`，320 步收敛。全过程无随机数，同一卡片库每次画出的图完全一致。

## 旧版为什么是「散乱堆积」

1. 半径 `3.5 + min(4, deg*1.1)` 在度 4 就饱和：5 连和 8 连的圆一样大，视觉上没有枢纽。
2. 向心力 `0.012` 压过排斥力 `1400/d²`，结果是一个半径均匀的圆饼：没有核心，也没有外围。
3. 拟合只缩放距离、不缩放半径 —— 图一大，点就并在一起，这才是「堆积」的直接来源。

## 三个必须守住的边界

1. **拟合必须连半径一起缩放**（`node.r * fit`），只缩距离等于把点合并。
2. **1/d² 要软化**成 `repel / (d² + 144)`。裸 1/d² 在初始重叠时是几千单位的加速度：实测包围盒冲到 8000、节点速度 1000+/步，画出来是一片飞散的碎片。
3. **向心力在远处封顶**（`min(distance, 220)`）。不封顶时大库里边缘节点被整段拽回中心，同样炸；封太小（如 3）又会让度数加权失效，核心-外围消失（实测 hubRadial 从 0.38 退到 0.43）。

## 规模上限

`density = min(1, sqrt(300 / max(300, linked.length)))` 让 300 张以内保持原比例，更多时半径与间隙一起收缩。实测：600 张不收缩有 18 处重叠，收缩后 0；800 张半径贴到 `1.2` 下限，画面退化成细密尘埃 —— 那是 canvas 只有 320×300 的物理上限，不是参数问题。

耗时（一次性，按卡片数组身份 memo）：44 张 5 ms、200 张 34 ms、400 张 78 ms。

## 验证

```bash
npm test
node harness/tool/link-layout-metrics.mjs
```

探针从 `client.js` 里直接抽出 `computeLinkLayout` 跑真实卡片库（不复制代码，不会漂移），输出 `overlaps / minGap / radiiByDegree / hubRadial / leafRadial / layoutMs`；`--svg` 另存一张图。判据：`overlaps: 0`、`minGap > 0`、`radiiByDegree` 随度数单调不减、`hubRadial < leafRadial`。

`test/client.test.mjs` 里新增的用例已经把「度数越大圆越大、节点互不重叠、不出画布、枢纽比叶子更靠中心」钉成断言；拿旧实现跑这条用例会红。

## 已知边界

- 数据本身以链为主（本库 44 个被链接卡片里 15 个是度 1），外围必然有散落的链尾和小孤岛，力导向无法把它们收进核心。
- 箭头是 7 单位、每条边都画，密度高时视觉噪声主要来自箭头而不是布局；要更安静得改 marker 尺寸或只在聚焦时画箭头。
