# 链接关系图的布局与视觉层级：六大枝干社区

## 适用场景

改概览页「链接关系图」（`client.js` 的 `computeLinkLayout` / `LinkGraph`）或宿主 `graph` 载荷时。

## 当前形态：纯图谱

面板上只有标题 + SVG，没有任何工具栏、图例、筛选、计数行或活动状态。用户明确要求「不需要搜索什么的，只需要单纯的图谱，优化的是图谱本身」，因此搜索/图例/弱关系开关/计数行/活动环/导出/重置按钮全部移除，宿主也不再读访问账（节点不再有 `readCount/lastReadAt`）。

读图靠四件事：枝干颜色分簇、簇上的枝干区域名、度数 top-N 的默认标签、hover/pin 的 1 跳高亮；再加缩放/平移。

## 布局：枝干就是社区

- **社区 = 六大枝干**。固定顺序 `['践行','见闻','即兴','复盘','觉察','试错']`，出现在图里的枝干按 360° 均分到锚点（中心 180×170，锚点半径 100）；枝干不被强行拉成上下左右固定方位，数量少时自动均分。
- **播种**：簇内按显式度数降序 + id 稳定排序；初始位置 = 锚点 + `cloudOffset`（黄金角 + FNV-1a(id) 抖动，`r=((i+0.5)/n)^0.66·contour`）× spread（`24+26·sqrt(簇大小/总数)`）。大簇云更大，小簇更紧。
- **四种力**（这是与旧「核心-外围」版最大的差别）：
  - 近距排斥：只在 60 单位内推彼此，远的簇不互推——分区由锚点负责，不再靠全局斥力。
  - 显式 link：短而硬（rest = `20+50(1-平均度权)`，k=0.05），真实关系决定形状。
  - 弱边（tag/branch）：长而软（rest = `14+26(1-平均度权)`，k=0.02），只让簇内松软，不抢形状。
  - 枝干锚点拉力：`0.040·(1-0.75·度权)·alpha`。叶子被锚在本枝干，枢纽更自由，能在簇间当桥。
- 340 步，`alpha=0.99^step`；积分 `x+=vx·0.45`、`vx*=0.82`；每 5 步分离 2 次；最后 4 次分离、按半径 fit 进 360×340（fit 上限 1.5、半径下限 1.3）后再分离 2 次。
- 半径 `r = 2.4 + 6.2·度权^0.75`；度权用显式 link 度数（载荷里的 `degree`）。没有显式链接的卡半径为下限，不抢视觉权重。

## 视觉层级

- **显式 link**：实线 1px、opacity .45、二次贝塞尔弯曲 6，两端按节点半径内缩；**箭头只在聚焦时出现**（hover/pin 的 1 跳边）。静止时全图没有箭头，画面安静；方向信息按需出现。
- **弱边**：虚线 `2 4`、0.75px、opacity .22、弯曲 3、无箭头。它是推断关系，只做背景纹理。
- **枝干区域名**：簇成员 ≥3 才画；同枝干色、opacity .35、10px、居中；位置取成员质心，再从 3 圈偏移里选离节点最远的位置；画在边与节点之下，用来分区而不是抢标签。
- **标签**：默认按度数取 top-N（`min(12, max(6, round(n/8)))`）；四方位 × 6 档距离搜索，避开节点圆、不互相重叠、不越界；截断 12 字，全名在 `title` 里。hover/pin 只叠加 focus + 1 跳邻居标签，不重排完整布局。
- **交互**：hover/pin 高亮节点 + 1 跳邻居，其余 opacity 0.16；滚轮缩放（指向光标）、拖拽平移、点空白重置视角；键盘 Enter/空格 pin；布局用 WeakMap 按载荷身份缓存。

## 为什么去掉外围能力（决策记录）

第二轮实现过搜索、枝干图例、弱关系开关、计数行、活动环、导出 PNG、重置视角；用户反馈只要图谱本身。于是：

- 这些控件不是「图谱」，而是围着图的工具；在小库上收益远小于视觉噪声。
- 活动高亮需要宿主读访问账并把 `readCount/lastReadAt` 塞进载荷，图谱却只用它染色——顺手删掉，宿主 `graph` 接口回到纯关系数据。
- 方向箭头从常显改为聚焦时显示：静止时的隐式全局信息让位于结构可读性。

**不要因为「别的图谱有这些」就加回来**；要加先确认需求。

## 确定性与规模

- 不使用 `Math.random` / `Date.now` / `new Date`（`test/client.test.mjs` 有源码守卫）；同一载荷两次布局完全一致，WeakMap 缓存让重渲染不重算。
- 实测（2026-11-12，本机真实库）：面板载荷 105 卡 → 105 节点 / 277 边（80 link + 197 weak），`branchCohesion 3.12`、`overlaps 0`、`minGap 5.57`、`span 294×314`、`28.2 ms`；单参旧口径 62 节点 / 81 边 → `cohesion 2.77`、`22.7 ms`。合成 300 节点约 70–90 ms。
- 判据：`overlaps: 0`、`minGap > 0`、`radiiByDegree` 随度数单调不减、多枝干时 `branchCohesion > 1.2` 且枢纽分支的半径更大。

## 验证

```bash
npm test
node harness/tool/link-layout-metrics.mjs                                    # 单参旧口径
node harness/tool/link-layout-metrics.mjs --graph /tmp/graph.json --svg /tmp/graph.svg
```

探针从 `client.js` 里直接抽 `computeLinkLayout`（不复制代码，不会漂移）；`--graph` 模式喂完整 `graph` 载荷，预览里能看到弱边虚线与枝干区域名。判据同上；`overlaps` 或 `branchCohesion` 破了就是布局回退，别只看「看起来差不多」。

## 已知边界

- 大簇（践行 30 张、即兴 38 张）仍偏散：cohesion 达标，但不是严格的分区；要更紧就调 spread 与锚点拉力，代价是跨簇边被拉长。
- 即兴簇多为零链接卡，靠枝干链弱边相连，画面上像散点——这是数据本身（真实库 39 张零链接卡）不是布局缺陷。
- 区域名选位只避开节点，不避开卡片标签，密集簇名仍可能被压。
- 箭头默认隐藏意味着静止时看不到方向，方向要 hover 才出现，是有意的取舍。
- 标签只覆盖 top-N，长尾卡靠 hover 的 `title`。
