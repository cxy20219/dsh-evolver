# 偏好的双写模式：入口与权威文件必须同内容

## 契约

DSH 每个会话开始读的是**入口文件** `~/.dsh/AGENTS.md`；权威数据文件在 `<dataDir>/system/AGENTS.md`。两种模式：

- **link**：入口是指向权威文件的软链，两边其实是同一份文件。
- **copy**：宿主没有建软链的权限（Windows 未开开发者模式、宿主受限），退化为双写——**入口必须是普通文件，内容与权威文件一致**。

入口就是 DSH 真正注入的那份内容，所以双写模式下两边不一致 = 面板改一份、DSH 注入另一份。这是双写模式的硬要求，不是风格问题。

## 曾经的缺口（已修）

迁移路径原来只写权威文件，没有同步入口：迁移后权威文件已剔掉旧受管段标记，入口却还留着旧全文，于是面板与 DSH 读到的内容不一致。这条 bug 只在**没有软链权限**的宿主上显形，有软链权限的机器走 link 模式看不到它——所以测试容易漏。

修法（`src/preferences.js`）：

- `prepare()` 判定为 copy 模式后，把权威文件的全文写进入口（`writeEntryCopy`），两边逐字节一致；
- 入口若是指向别处的软链，换成普通文件：它原来指向的文件留在原地，只有入口这个注入点被接管，与 link 模式重新指向同一件事；
- 入口内容已经一致时不重写，避免每次读偏好都改动 mtime；
- copy 模式的写入目标统一是入口路径（`destination`），不再有「软链写穿到别处」的分支。

## 测试怎么覆盖

`readPreferences` / `writePreferences` 接受 `allowLink: false`（默认 true），用来**不依赖宿主权限**地强制走双写模式。`test/preferences.test.mjs` 里「没有软链权限时，入口文件与权威文件是同一份内容」这条用例因此在任何机器上都会真正跑到 copy 分支——包括有软链权限的机器。

教训：凡是「某台机器才有」的路径，都要给一条**不依赖该机器能力**的入口，否则回归会静悄悄溜过去。
