# Ziyan Evolver

## 职责

维护一个**跨项目**的知识库：把已验证、以后还会用到的经验、流程、脚本、事实判断存进去，并在需要时检索出来直接用。

与 `harness-evolver` 的分工是**范围**，不是内容：

| | 存哪里 | 给谁 |
|---|---|---|
| `ziyan-evolver` | 自衍中枢库（跨项目、跨会话） | 所有项目、所有 agent |
| `harness-evolver` | 目标项目的 `harness/`（随仓库走） | 只服务那一个项目 |

一条经验如果只在一个仓库成立 → 项目的 `harness/`；如果换一个项目还会踩到 → 进库。

## 边界

- **只存高信号内容**：能减少未来误判、重复劳动或验证成本的东西。不记流水账、一次性命令、临时猜测、未验证方案。
- **不存**密钥、令牌、私有配置、完整日志、完整对话转录。
- 项目内的决策写项目自己的目录；库只收跨项目可复用的部分。不要把一个项目的目录结构、内部命名、私有路径塞进库。
- 写入前必须查重：能更新就不新建。
- 拿不准要不要存时，先检索；检索到相似条目就补进去，检索不到再判断。

## 命令

`ziyan` 是命令行入口，四个动词直接对应库操作：

```bash
ziyan search "<查询>" [--tags a/b,c] [--limit 20] [--graph] [--json]
ziyan read <id|短id> [--raw] [--json]
ziyan write <文件|-> --desc "以后什么时候用" [--name x.md] [--tags a/b] [--links id] [--json]
ziyan write --from <宿主文件> --desc "..." [--json]
ziyan edit <id> [--old "旧" --new "新"] [--desc "..."] [--tags a/b] [--archive|--unarchive|--remove]
ziyan stats
```

通用参数 `--data-dir <绝对路径>`；不传时按 `~/.ziyan`、其次 `~/.dsh/ziyan` 自动选择。环境变量 `ZIYAN_DATA_DIR` 同样有效。

### 命令不可用时

先用 `ziyan stats` 确认。失败说明命令不在 PATH，按顺序尝试：

1. `node <仓库>/bin/ziyan.mjs stats` —— 仓库就是本 skill 的来源仓库（含 `bin/ziyan.mjs` 的那个）
2. 仍不行就告诉用户「ziyan 命令未安装」，并给出一次性安装建议：`ln -sf <仓库>/bin/ziyan.mjs ~/.local/bin/ziyan`（或加入 PATH 的任意目录）

**不要**为了绕过缺失的命令去直接读写库目录（`files/<id>/meta.json`）：边车与索引的一致性由命令维护，手改会留下索引与事实不一致的脏数据。

## 硬性约束

- **描述写「以后什么时候会用到它」**，不写「它是什么」。正文已经参与检索，重复正文没有收益；描述是检索的第一排序面（权重 10 : 6 : 2），写准才排得前。
- 描述用**以后会搜的词**：「排查 X 时先看」「给 Y 定方案前读」「出现 Z 报错时」。
- **至少一个标签**，层级路径用 `/`（如 `来源/harness`、`践行/踩坑`）。
- 相关文件用 `--links` 连起来，别留孤岛。
- 写入前先 `ziyan search` 查重；已有条目就 `ziyan edit` 更新，不要新建同义条目。

## 执行流程

### 一、开工前：先搜

```bash
ziyan search "<任务的关键名词>"
```

关键词用**任务本身的词**，不要先翻译成你猜的术语。命中就 `ziyan read <id>` 取正文，按里面的结论做，不重造。

搜索结果里 `↳n/↰n` 是出边/入边数，度数高的条目通常是这个库的中心概念，值得优先读。

### 二、任务中：判断要不要沉淀

满足任一条才沉淀：

- 验证过的判断，换一个项目还会用到
- 稳定流程或命令序列，下次能直接照做
- 踩过的坑，再遇到会重复浪费时间
- 第三方工具/协议的边界事实（什么能做、什么不能做、为什么）

不满足就跳过，不要为了「有产出」而写。

### 三、写入

```bash
ziyan write ./note.md \
  --name "mcp-error-field.md" \
  --desc "排查 MCP 服务端返回成功但面板不刷新时看：error 是信封保留字，监听失败要换个字段名" \
  --tags 见闻/工具怪癖,来源/harness
```

内容直接读文件；从标准输入用 `-`；从宿主已有的文件搬进来（不复制正文）用 `--from`。

写入返回 `⚠` 警告时（描述太短、缺场景词、死链）当场改掉，不要留着。

### 四、关联

新条目如果与已有条目相关，补上链接：

```bash
ziyan edit <新id> --links <旧id>
```

链接是双向可视的（另一侧会显示「被引用」），只写一边就够。

## 输出格式约定

- 默认文本输出是给人读的；需要解析时加 `--json`。
- `read` 默认输出「元数据 + 正文」，只要正文加 `--raw`。
- 所有命令失败时退出码非 0，错误写 stderr——可以直接用 `&&` 串起来。

## 常见误用

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 把只在本项目成立的约定存进库 | 别处按错误前提行动 | 写项目的 `harness/` |
| 描述写「XX 的说明文档」 | 以后搜不到（没有场景词） | 写「什么时候需要它」 |
| 同一个坑存三条不同名字的条目 | 检索时互相稀释 | 先搜，能合并就更新一条 |
| 直接编辑 `files/<id>/meta.json` | 索引与事实不一致 | 只用 `ziyan edit` |
| 把整段对话或长日志存进去 | 库变成仓库，检索失效 | 提炼成判断，正文短 |
