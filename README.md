# dsh-evolver

自我演化控制台：一个插件、一个侧边栏入口、一套统一的卡片知识库。

每次请求注入两块：一块静态的**系统段**（卡片纪律 + 主动性协议，只在发版时变），一块运行时的**卡片索引**
（关系最多的 8 张卡：短 id/标题/描述/关系数 + 一段知识结构摘要，跟随每日快照）。标签树不再注入——它随
枝干增长而变长，却不是模型脑子里缺的那部分；标签目录用 `card_index` 取（大库按 `tag` 逐枝钻取），具体内容用 `card_query` / `card_read` 取。

```
~/.dsh/evolver/                  ← 唯一数据目录（迁移 / 云备份的单位）
  knowledge/
    cards/cards.jsonl            ← 卡片日志：追加写，最后一条同 id 记录生效
    resources/<card-id>/         ← 卡片附件
    tags.json                    ← 标签描述（可选，覆盖内置默认）
    consolidation.json           ← 卡片复查台账（谁在什么时候看过哪张卡）
    consolidation.jsonl          ← 卡片整理动作审计（每次改了什么、为什么）
    index.json                   ← 注入快照：卡片索引（top cards + 结构摘要）
    access.json                  ← 卡片被读过的次数与最近一次（整理排期用）
    trash.jsonl                  ← 卡片整理/删除的正文副本（先写副本，再删卡）
    trash-resources/             ← 被删卡片的附件回收目录（同样先归档再删）
  sight/sessions.json           ← 会话整理游标（只由自动整理推进）
  preferences/AGENTS.md         ← 全局偏好（链到 ~/.dsh/AGENTS.md）
```

## 卡片模型

一张卡是一行 JSON，**没有分类字段，也没有标题**；分类全由层级标签表达：

```json
{
  "id": "card-01M72KRG4VQEQQ25BM3DTHB97X",
  "body": "正文",
  "tags": ["践行/工作流"],
  "links": ["card-01..."],
  "updated": "2026-11-10T13:40:16.269Z"
}
```

- **id** ULID；`created` 从前 10 位派生，不存。
- **body** 正文；`label` 从首行派生，不存。
- **tags** 唯一的分类入口。**顶层只允许六个枝干**：`#践行` `#见闻` `#即兴` `#复盘` `#觉察` `#试错`。
  父标签自动包含子标签，`#践行` 能搜到 `#践行/工作流`；归档写 `<枝干>/归档`，不要造第七个顶层。
  枝干最多三层（枝干/主题/子题）、名字用中文名词/动宾短语（标点会被规范化成 `-`）；`#即兴` 是收件箱，落定后要摘掉。
  从旧库/导入数据里继承到非法顶层标签时，写卡按**确定性降级**处理：该标签重新挂到 `#即兴` 下并记一条 warning，卡本身照常保存。
- **description** 可选，一句话说明这张卡讲什么、什么时候值得读（≤120 字，单行）。进 BM25 检索、
  搜索结果和注入的卡片索引；不写也能用，但写了的卡在「关系最多」之外多一个被找到的理由。写入与读路径都会做单行化、控制符清洗与密钥筛查。
- **links** 卡片 id 数组，空则不写；反链实时计算。孤立的卡等于埋在库里。
- **source** 可选，`{ "quote": "...", "session": "..." }`：逐字出处（≤160 字）与来源会话 id。两个来源：会话整理提取时
  模型抄回的一句原话（抄不到就整条丢弃，不编造），或 agent 用 `card_write` 时传的 `quote`。
  每天的整理会按 `session` 取回那句话前后的一段摘录（只读、截断、抹密钥）做对照，发现正文说反/说过头才改——
  卡片本身无法证明自己有没有记错。
- 没有 `type`/`status`/`category`/`summary`/`resources` 之类字段。

### 附件

文件放在 `knowledge/resources/<card-id>/`，正文必须写引用行，缺引用会被拒绝写入：

```text
[标题](knowledge/resources/<card-id>/<文件名>)：用途：...；入口命令：...；输入：...；输出：...；关联流程：...
```

- 路径相对**数据目录**。写卡时可用 `{{resource}}` 占位，落盘替换成最终路径。
- `card_read` 同时返回绝对 `path` 和 `executable`，执行时用绝对路径。一次 `card_read` 的附件文本总预算 256 KB，
  超出部分只留元数据（名称/字节/sha256/path），正文不返回。
- 脚本与原生可执行文件自动 `0700`，普通文档 `0600`。
- 读附件前会确认资源目录真的在数据目录内（软链或越界一律拒绝）。

## 注入与检索

| 部分 | 载体 | 预算 |
| --- | --- | --- |
| 纪律 + 指向工具 + 主动性协议（静态，一段） | `systemPrompt.section` order 900 | 2 KB（纪律 0.7 KB + 主动性 1 KB） |
| 卡片索引：关系最多的 8 张卡 + 结构摘要 | `systemPrompt.context` order 900 | 4 KB（真实 95 卡库实测 1366 B） |
| 全局偏好 `preferences/AGENTS.md` | DSH 的 `dsh-agent-instructions` | 64 KB |

**为什么是卡片索引，不是标签树。** 标签树回答「知识怎么分类」，卡片索引回答「这个库里最该先读什么、
它和什么有关」：每行一张关系最多的卡（`card-…` id + 标题 + 描述 + 关系数），`card_read` 一次就能落下去；
随后一段知识结构摘要（枝干与规模）给结构感。

**快照什么时候写。** 索引读的是 `index.json`：每日整理写它；另外每次打开数据目录（首次启动、迁移、
导入、切换）都会先建一次，所以新库的第一个请求不用在全库上现排序。快照内容没变就不重写文件；
写卡当天不改快照，因此不会打断请求前缀缓存。快照缺失/过期/损坏时回退实时排序——这条回退按 store
版本 + 当天记忆化（2000 卡无快照 43.8 ms → 3.3–4.3 ms，缓存命中 0.04 ms）。

**id 用短写。** 完整 ULID 是 31 字符，8 条就是 248 字节纯地址；注入只显示**唯一后缀**（5–8 字符，
如 `Q7CTP`），`card_read`/`card_write`/`card_query within` 等工具都接受这个缩写——按后缀匹配，
唯一才解析，撞了直接报错让人用完整 id，不猜。短 id 在生成快照时按后缀计数重算（O(N·8)，2000 卡
解析从 44 ms 降到 1.5 ms 量级），完整 id 仍是存储与链接的权威。

**降级顺序**（超预算时先省信息密度，不砍结构）：

1. 先丢掉卡片描述，保留 id/标题/关系数；
2. 再减少卡片行数；
3. 结构摘要永远保留——它是一段话，丢了就没有全局；
4. 全部展开也放不下时，写一句「其余卡片未展开：card_query 看内容」。

`card_index` 返回预算内的标签目录（路径、计数、说明）：超预算时按「省说明 → 少层 → 提示钻取」降级，`tag` 可钻取单个枝干；不重复渲染注入段。`evolve_review` 和概览会给出
「卡片索引 / 卡片正文」的占比：索引持续变大说明知识密度在下降，该合并了。

超限不会悄悄变大：正文超了直接拒绝写入。任何卡片正文都不自动注入——需要时用 `card_query` 取。

## 检索：关键词 + 双链关系图

搜索有两段：**BM25 词法命中**（中文 bigram + 按最近访问的 recency 加权 + MMR 去重），然后**沿双链扩散**。
词法找到「说了这些词的卡」，扩散找到「和这些卡关于同一件事、但没说到这些词的卡」：

- `card_query` 默认返回命中卡（带 `degree` 入/出链数）；
- `card_query graph:true` 返回 `{ cards, related, graph }`：命中卡 + 一跳邻居 + 子图（节点带
  id/标题/描述/关系数，边是真实链接）；`hops` 1–3 控制扩散范围；
- `card_query within:[id…]` 在这一批卡里做二次搜索——先粗搜、再看图、再在子图里深挖。

扩散用**带衰减的个性化游走**（种子按词法分归一化，每跳 ×0.55，再加 log 度数的枢纽加成）：
一跳邻居永远压过二跳，被多个种子同时指到的卡会被加强。没有 embedding——在这套库上实测
embedding 只改变排序、不改变召回，却要 592 MB 和启动停顿；双链是库自己维护的数据，扩散就是它的回报。
也没有 rerank hook：唯一的候选打分就是 BM25 + 图扩散。

## 记忆分层与每日整理

对齐 Anthropic《The components of agent memory》，本插件只保留其中两层是自己的：

| 层 | 本插件里的东西 | 谁维护 |
| --- | --- | --- |
| 会话记录 | 宿主会话日志 + `session_digest` | 宿主 |
| 笔记 | 卡片 | agent / 会话整理 |
| 注入 | 纪律 + 主动性协议 + 卡片索引（`index.json` 快照） | 每日整理写快照；打开/迁移/导入数据目录时也建一次；请求只读 |

> 曾短暂做过「枝干页」表示层（每个 ≥5 张卡的枝干一张索引卡），因与搜索/注入的收益不成正比已移除，本文不再描述它。

每日整理（dreaming）现在是一个流程两段：

1. **整理批次**：按「从未复查 → 最久未复查 → 最久未编辑」选卡，被读过（`access.json` 里 14 天内）的卡降权最多 30 天，避免热卡被无限推迟（`access.json` 由访问账自己 flush，整理只读）；
2. **修复轮 + 快照**：清死链，最后重写 `index.json`（内容相同不重写）。

## 工具

共 13 个：9 个卡片/会话工具、1 个缓存诊断工具、3 个维护项目 `harness/` 的工具。

| 工具 | 作用 |
| --- | --- |
| `card_query` | 词法检索（BM25 + 标签过滤）与关系图检索：`graph:true` 返回相关子图，`hops` 控范围，`within` 做二次搜索；结果带 `degree` |
| `card_read` | 读一张卡（id 可传注入里看到的唯一缩写）：正文、链接、附件；`neighbors:true` 附带出链/入链，可顺链跳转；附件文本总预算 256 KB |
| `card_write` | 写入/更新；分类由 tags 表达；可带 `description`（一句话说明，进检索与注入索引）与 `quote`（逐字出处） |
| `card_index` | 标签目录（一行一个标签：路径、卡片数、说明），在 2 KB 预算内自适应；超预算先省说明再少层，可用 `tag` 钻取单个枝干；不含卡片正文 |
| `card_promote` | 把 `#即兴` 移入六大枝干之一 |
| `card_archive` | 加 `<枝干>/归档`，保留记录和资源 |
| `card_remove` | 永久删除一张卡片及其资源附件（不可恢复；整理器的删除走回收站副本，工具删除不走） |
| `cache_report` | 当前会话的提示词缓存命中情况：每步输入/缓存读/缓存写、总命中率，以及哪些步缓存全丢（用来判断注入块是否稳定） |
| `evolve_review` | 一次拿到库盘点与可执行 hints |
| `session_digest` | 读取没整理过的会话摘录；只读，不推进游标——游标归空闲时的自动整理独占 |
| `harness_catalog` | 扫描项目 `harness/` 资源系统现状（分层文件、标题与用途、AGENTS.md 索引差集、缺失/多余项）；写 harness 资源前必须先调用 |
| `harness_write` | 写入/更新一条项目 harness 资源，自动重建 AGENTS.md 索引并校验；校验不过回滚并报错 |
| `harness_validate` | 校验 `harness/` 结构、AGENTS.md 索引完整性、脚本文档契约与 Python 语法 |

## 两个后台整理器

都在「整理」页里开关，各干各的（这个页签在设置左边）：

- **会话整理**：宿主 15 分钟无会话活动、且有没整理过的会话时，直接调用当前默认模型做一次
  受限提取，把偏好/纠正/结论写成 `#即兴` 卡。不创建会话、不给工具，所以不会在后台读文件或跑命令。
  游标在 `sight/sessions.json`，只有自动整理会推进它；一次最多 10 个会话、6 张卡。
- **卡片整理**：每天固定时刻复查一批卡片（默认 15 张），只做五件事——删掉没用的、合并重复的、
  补双向链接、**只改标签把卡落定到对的枝干**（`retag`，不碰正文）、必要时再改写正文。模型只返回
  JSON 动作，插件逐条校验。
  - 删除是「先写副本、再删」：正文整条先追加进 `knowledge/trash.jsonl`（附件先进 `knowledge/trash-resources/`），
    副本写失败时卡片保持不动，不会出现无副本删除。
  - 动作逐条独立：单张卡失败只跳过该卡并记审计，不阻断整批。
  - 标签不是自由生长：已有枝干优先，一次运行最多新建 1 个枝干、最多三层、必须带一句说明（写进
    `tags.json`）；`<枝干>/归档` 由卡片整理来写一律拒绝；两个枝干其实是同一件事时用 `tag-merge`
    合并（一次最多一个）：先把要改的卡全部收集并校验完，再开始写，写到一半失败不会把库拆在两个枝干上；
    单卡写入失败跳过并记录。合并会把说明一起搬走。
  - 每条落库动作都会追加一行到 `knowledge/consolidation.jsonl`，所以「上次整理到底改了什么」可查。

会话整理默认开、卡片整理默认关（它会改卡片库）。两者共用一个判据：**三个月后还成立吗**——
所以记录的是规则和判据，不是「界面现在长什么样」。

## 设置

「设置」页三个子标签：数据目录、导入 / 导出、云端备份。整理器不在这里，它是设置左边的独立页签。

- **数据目录**默认 `~/.dsh/evolver`；迁移是先完整复制再切换，旧目录原样保留可回滚。
- **导入 / 导出**用 `.tar.gz`，包内只允许写 `knowledge/`、`sight/`、`preferences/`；导入有体积与条目上限（见「边界」）。
- **云端备份**把整个数据目录打成一个标准 tar 传 OSS（V1 签名；`http(s)://` 完整地址走路径风格，兼容 MinIO）。
  endpoint 接受裸 OSS 主机名或完整 `http(s)://` 网关地址，拒绝带用户名/密码的 URL；非 loopback 的 `http://`
  会自动升级成 `https://`（否则签名和 AccessKeyId 会明文上路）。OSS 错误响应体最多读 8 KB。
  密钥只写本机 `~/.dsh/evolver.config.json`（0600），不回传浏览器，也不会被打进备份。

设置文件 `~/.dsh/evolver.config.json` 不在数据目录里：移动数据目录不丢设置，云备份也不带密钥。

## 边界

- `dataDir` 必须是绝对路径。数据目录与偏好目录按 `0700`、配置文件/卡片库/偏好文件按 `0600` 创建（设置文件的 `0600` 已有测试断言；数据目录的 `0700` 目前只有设计约束）。
- 请求体：插件按请求头声明的 `content-length` 拒绝超过 16 MB 的请求；宿主 `buffered` 模式本身还有约 300 MB 的读取上限，真正的内存保护靠宿主。
- 附件单文件 **10 MB**（解码后）；面板在选择文件时先拒绝大于 8 MB 的文件。`card_read` 的单卡附件文本总预算 256 KB，超出只回元数据；单个文本资源超过 512 KB 或含二进制内容时也按 binary 只回元数据。
- 压缩包导入：包 ≤ 2 GB、解压后 ≤ 1 GB、≤ 2 万条目、单条目 ≤ 64 MB；包内非普通文件条目（软链等）跳过，目标位置已有软链时一律不覆盖。
- 密钥筛查在写卡入口：私钥块、GitHub 令牌、AWS `AKIA…` 与 `aws_secret_access_key`、阿里云 `LTAI…`、Slack `xox*`、`sk-…` API key、JWT、`Bearer …` 一律拒写；读取会话摘录时按同一组模式脱敏。
- `~/.dsh/AGENTS.md` 只在「不存在」或「是普通文件」时自动接管（原文件先备份为
  `preferences/AGENTS.md.imported`）；已被别的工具链接时不抢，面板里点「接管」才替换。
- 面板容错：某个接口读取失败时只在顶部提示「部分数据读取失败」并保留其余页签，可点「重试」；首屏加载失败也有重试入口。

## 安装

```bash
dsh plugin --profile web add /path/to/dsh-evolver
dsh plugin --profile web why dsh-evolver     # 确认行状态
```

详见 [INSTALL.md](INSTALL.md)。首次启动创建数据目录、种下三张种子卡，并把 `~/.dsh/AGENTS.md`
链到 `preferences/AGENTS.md`。
