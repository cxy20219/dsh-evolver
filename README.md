# 自衍中枢 · dsh-ziyan

> 全面改名：包名 `dsh-ziyan`、客户端 id `dsh-ziyan`、API `/api/ziyan`、数据目录 `~/.dsh/ziyan`、指针 `~/.dsh/ziyan.home.json`。旧目录 `~/.dsh/yuanshi` 只作为备份保留，不再读取。

一个「一切皆文件」的知识库插件：每个文件有唯一 id、一句话描述、自由层级标签，文件之间可以互相链接；插件只维护描述索引与关系，正文由 agent 自己读、解析、执行。

## 状态

- **Host 半边已实现**：数据目录、文件存储、SQLite 索引、描述检索、图遍历、**4 个工具**（`file_search` / `file_read` / `file_write` / `file_edit`，一套动词同时服务文件库与项目文件）、一段静态注入、设置、日志、28 个面板接口、会话外整理引擎与自动调度，以及一个默认关闭的 MCP 端点（让别的 agent 调用同一套库动词）。**运行时不再注入文件索引**：agent 需要文件时用 `file_search` 自己搜。
- **面板（浏览器半边）已实现**：侧边栏「自衍中枢」，概览 / 图谱 / 文件 / 注入 / 自衍 / 设置 / 日志七个页签；可搜索、编辑、上传、新建、归档、删除、看图；自衍页可选整理模型与思考强度、开关自动整理、看作业结果。
- 数据目录默认 `~/.dsh/ziyan`，一个根目录下分两棵子树：`files/` 只放文件本体，`system/` 放索引与系统数据。

```
~/.dsh/ziyan/
  files/<file-id>/<name>       文件本体
  files/<file-id>/meta.json    边车元数据（事实来源）
  system/ziyan.db            SQLite 索引（可删、可重建）
  system/settings.json         设置
  system/organize-jobs.json    整理作业记录（含自动调度）
  system/organize-ledger.json  自动整理台账（哪些会话已整理到哪个版本）
  system/logs/plugin.log       插件日志
  system/trash/<时间戳>-<id>/  删除回收站
```

## 规则

- 每个文件：`id` + `description` + 至少一个 `tags`；`tags` 是自由层级路径，例如 `工作/项目/自衍中枢`、`类型/脚本`。
- 搜索只命中 name / description / tags，不索引正文，也没有 snippet。
- `links` 是出边，目标可以是任何类型的文件；反链实时计算；死链/自链写时丢弃并进 `warnings`。
- 脚本按扩展名/shebang 设 `0700`，`file_read` 返回 `path` + `executable`；插件不执行脚本。
- **自衍中枢只管库**：职责只有三件事——**存有价值的文件、需要时找得出、agent 读出来就能直接用**。项目内的知识不进库；库只收跨项目可复用的经验、流程、脚本。
- **项目 harness 归项目自己**：`harness/` 是普通目录，用什么结构、谁来维护（项目的 skill、别的 agent、编辑器）由项目决定。插件**不建骨架、不写边车、不生成索引、不做校验**；`file_write` 写到项目路径就是普通文件写入。项目根的 `AGENTS.md` 仍由 DSH 注入，但插件不再生成它，也不拒绝手写。
- **库文件的描述契约**：`meta.description` 要写清「它是什么」+「以后哪些场景、任务、问题会用到它」（写成以后搜索时会输入的话）；短且无场景词的描述会被工具以非阻断 advice 提醒。从项目搬进库用 `file_write({from:"..."})`。工具名保留 `file_` 前缀是为了不与 DSH 内置的 `read`/`write`/`edit` 同名。

## 工具与面板

Agent 工具只有 4 个：`file_search`（检索/规模统计/图）、`file_read`（库文件或项目内路径）、`file_write`（建/改库文件、导入、写项目文件）、`file_edit`（正文精确替换——库文件与项目文件都适用，改一段不必重写整篇；再加描述/标签/links/归档/删除）。

面板通过 `/api/ziyan/*` 的 27 个接口工作：文件 7 个、概览/图谱/设置读写/日志 5 个、注入 2 个（`injection`、`tools`）、偏好 2 个（`preferences`、`preferences-save`）、自衍与整理 7 个（`digest` + `organize-*` 6 个）、数据 4 个。浏览器只发 id，不发文件路径；上传、预览和归档都有大小上限。

### 面板

顶层页签固定为 **概览 / 图谱 / 文件 / 注入 / 自衍 / 设置 / 日志**。

- **概览**：记录热力图、文件/标签/天数三项统计，以及按文件后缀区分的类型面积矩阵。整页按视口高度铺满：热力图与统计保持自然高度，矩阵吃掉剩下的空间（容器变化时重算 treemap，不会拉伸变形）。点矩阵里任意一块，跳到「文件」页并把「类型」下拉切到那个后缀。标签统计的是**不同标签路径数**。
- **图谱**：三个子标签。「星球图」把全部文件铺在可旋转的球面上，按标签根聚团；「关系图」是同一批节点的力导向网状布局，可平移、Shift + 拖拽旋转、缩放；「标签图」是标签层级，点标签按它筛选文件。前两个是 canvas：节点按链接度数定大小与质量，**占位碰撞保证同一处不叠两个点**，小节点被大节点吸引、无关节点互相排斥，簇由链接自然形成；连线是绿色的、在圆点边缘截断；悬停某个节点时它的边点亮并画出方向箭头，节点环和名字也变绿；点节点打开文件。
- **文件**：搜索描述/名字/标签、标签前缀、类型、显示归档。「类型」下拉就是库里的后缀清单（`.md · 740` 这种带计数），选它即筛选，与关键词、标签可叠加。列表占满整页不滚动，每页条数按列表高度算，底部翻页；点一行从右侧滑出详情抽屉（改描述/标签/出链/正文，保存、归档、删除），Esc 或「关闭」收起；上传、新建也在这一页。
- **注入**：三个子标签。「提示词」只展示插件注入的**一段静态系统纪律**（按 DSH 全局 `AGENTS.md` 的风格写：`# 自衍中枢` 总则 + `## 记忆` / `## 沉淀`；每轮都带，显示为 token 估算），并说明运行时不再注入文件索引——需要文件时用 `file_search` 按描述/标签/links 自己搜；项目依赖与约定由项目自己管理。没有运行时索引、快照与注入预算。「工具」列出插件向 DSH 注册的 4 个工具（`file_search`/`file_read`/`file_write`/`file_edit`）及其 schema 的 token 估算：分类（只读/写入）、一句话功能、参数（可展开）；数据来自工具定义本身，不会与工具面漂移。「偏好」编辑 DSH 全局 AGENTS.md 的全文：数据统一存在自衍数据目录的 `system/AGENTS.md`，`~/.dsh/AGENTS.md` 软链到它（不能建链时退化为两边同步写），所以面板显示的就是每个会话开始时注入的规则；显示当前草稿的 token 估算与字节上限。
- **自衍**：三个子标签。「整理台」形态与旧 evolver 的整理页一致——三张卡：整理模型（服务商 / 模型 / 思考强度，默认跟随聊天）、会话整理（自动开关 + 空闲分钟数 + 立即整理）、文件整理（自动开关 + 每天几点 + 立即整理）。「最近作业」单独成子标签：最多 5 条作业（状态、结果计数、失败原因、运行中可取消，日志折叠），可手动刷新。整理作业**在会话外**由宿主用选定模型跑工具循环，自动开关默认关；打开后宿主按空闲/每日自动触发，台账在 `system/organize-ledger.json`。页面上**没有**重建索引、重建快照、重新读取、演练模式等手动维护按钮：索引需要时自动重建，整理交给 agent 作业。「提示词」只读展示整理作业实际使用的系统提示词：会话整理、文件整理、收尾轮指令（正常 / 预演）与各自的 token 估算，并说明用户消息按作业动态拼接（会话转录 / 库整理报告）——和模型侧完全同源，方便审计「自衍到底被要求了什么」。
- **设置**：描述上限、单文件上限、读取上限；保存后立即生效。
- **日志**：`system/logs/plugin.log` 尾部。

## 数据目录与备份

默认数据目录 `~/.dsh/ziyan`。设置页分「常规 / 数据」两个子标签；「数据」子页可以：

- **复制当前库到新目录**：只复制 `files/` 与 `system/settings.json`，DB、索引、日志、回收站由下次启动重建；目标目录必须不存在。
- **使用已有自衍中枢库**：目标必须已经有 `files/`，不复制、不覆盖。
- **导入 `.tar.gz`**：解压到新目录，校验后切换；旧库保留。
- **导出 `.tar.gz`**：包含 `files/` 与设置，不包含 DB、索引、日志、回收站；浏览器直接下载。

目录切换都写一个指针 `~/.dsh/ziyan.home.json`，**重启后生效**；当前会话继续读旧库。指针是唯一放在数据目录外的文件，内容只有一个绝对路径；删掉它即可回到组合配置/默认目录。

导出包限制：归档 ≤32 MB、解压 ≤256 MB、单文件 ≤64 MB；导入会拒绝绝对路径、`..`、反斜杠、符号链接和非普通 tar 条目。

## 性能与规模

索引是派生数据，设计目标是**读路径不随库大小线性退化、重建成本与文件数线性**。实测（Ryzen 7 5800H / Windows 11 / Node 22，`node scripts/scale.mjs` 合成库，p50）：

| 指标 | 10k | 100k | 1M（DB 级） |
|---|---|---|---|
| 列表首页 / 尾页 | 0.9 / 1.1 ms | 2.9 / 16 ms | 43 / 158 ms |
| 搜索（关键词 / +标签） | 11 / 14 ms | 37 / 70 ms | 55 / 222 ms |
| 标签过滤页 | 7.7 ms | 64 ms | 748 ms |
| 概览 / 图谱端点 | 1.5 / 49 ms | 14 / 77 ms | 144 / 134 ms |
| 单次写 | 0.7 ms | 0.92 ms | 3.8–11 ms |
| 冷启动（scan + rebuild） | 3.0 s | 37.5 s | — |
| 峰值 RSS | 162 MB | 503 MB | 823 MB |

- FTS 与 `files` 的 rowid 对齐、按 rowid 写/删；重建走一条 `INSERT ... SELECT`：1M 行建 FTS 约 62 s（旧实现外推 ~60 h）。
- 10k/100k 是真实文件系统库（边车 + 载荷 + 索引）；1M 默认 DB 级合成，验证查询计划/内存/索引体积。真实 1M 文件系统库（1,000,000 实体 = 2,000,000 文件）也可用 `--tier 1m --mode fs --force-fs` 跑：生成约 44 min（文件树逻辑 1.15 GiB、NTFS 实占约 8.3 GB、索引 1.61 GiB），warm 读路径 open 64 ms / 首页 45 ms / 尾页 171 ms / 搜索 47 ms / overview 143 ms / 单写 3.98 ms。
- 🚧 **已知瓶颈**：1M 真实库的**冷启动** scan ≈36.6 min（2M 个小文件首次 IO + 16 路并发 + Windows Defender 实时扫描；`readdir(1M)` 只需 3 s），加 rebuild 合计约 38–42 min；日常 100k 库冷启动 37.5 s。后续方向是增量/离线 rebuild 与后台扫描。
- 复现：`node scripts/scale.mjs --tier 10k --reset`、`--tier 100k --reset`、`--tier 1m --reset`；并发/崩溃/损坏/泄漏压测 `node scripts/stress.mjs --tier 100k`；1M FS 用 `--tier 1m --mode fs --force-fs --reset`。数据只写 `.scratch/scale-data`，脚本拒绝与真实库目录重叠。

## 安全与可靠性

- 面板接口只收 id/结构化参数；上传、预览、导入先 stat + realpath + 大小预检再读，拒绝目录/设备/管道/越界符号链接；归档导入拒绝绝对路径、`..`、符号链接与非普通条目。
- 项目路径必须落在项目根内（会话 cwd 的祖先，realpath 判定），越出项目根拒绝。
- 整理作业每轮/整作业都有超时与看门狗，取消或崩溃后会回收互斥锁与台账；自动整理默认关，导入归档里的 settings 不会打开自动整理、也不会覆盖本机模型。
- 数据库损坏或 schema 不匹配时：关闭句柄 → 旧库改名 `ziyan.db.corrupt-<时间戳>` → 从边车重建索引 → 插件继续加载；写入的文件/SQL 全部参数化，文件名净化拒绝 Windows 保留名与 ADS。

## 开发

```bash
npm test                       # 全部测试
node scripts/bench.mjs 500     # 500 文件基准
node scripts/scale.mjs --tier 10k --reset   # 规模基准（见上）
node scripts/stress.mjs --tier 100k         # 并发/崩溃/泄漏压测
```

安装到目标 profile（先不要动 desktop profile）：

```bash
dsh plugin --profile <profile> add /path/to/dsh-ziyan
```

装完重启 DSH；左侧边栏会出现「自衍中枢」。
